# 说明书写作规范（含禁词表与自检）

## 一、章节骨架（审核友好，10 章）

1. 软件概述（含**相关文档表**、术语与缩略语、产品边界）
2. 运行环境（硬件/软件、**系统要求最低-推荐配置表**、兼容性、权限）
3. 系统架构与技术特征（分层、技术栈、数据与证据模型、状态机）
4. 功能模块说明（按真实页面，一模块一节）
5. 操作流程（逐页配截图，按真实流程分步）
6. 报告与业务规则（分层、门控条件、缺失/冲突处理）
7. 数据管理与隐私
8. 行业/医学边界与免责声明
9. 异常处理
10. 版本维护 + **常见问题解答**

篇幅 35–59 页；xelatex 编译两遍，第二遍目录页码才正确；每页正文 ≥30 行。

## 二、写作红线

- **段落化**：每个页面/模块写"使用场景 + 页面用途 + 进入位置 + 页面内容 + 用户动作 + 状态规则 + 系统反馈"，但必须合并成自然段落。
- **禁止字段表式小标题**：`进入方式：`、`操作步骤：`、`页面内容：`、`操作规则：`、`操作结果：`、`使用场景：`。
- **禁止空泛口号**（`lint_manual.py` 会扫）：旨在、赋能、一站式、智能化、高效便捷、显著提升、强大能力、强大功能、丰富功能、全面提升、无缝、极致、引领、助力、全方位、深度赋能。
- 每个模块写到**具体控件、状态标签、提示文案、异常反馈**，不同模块不许同一句式复读。
- 不得虚构未实现功能；规划能力必须写"后续规划/待实现"。
- 医学/安全类软件必须写：非诊断设备、不替代专业判断、不输出什么指标（如 Cobb 角、ATR）。
- 允许保留的占位只有 `【著作权人姓名】`；`TODO / 待补充 / Lorem / XXX` 一律不允许。

## 三、自检（交付前必跑）

`python lint_manual.py` 会检查：

1. tex 源里的禁词、字段表式小标题、占位符（输出文件:行号）
2. PDF 页数是否在 35–59、每页非空行是否 <30（列出页码）
3. 每页是否命中软件名页眉
4. 内嵌图片数量（截图应真实嵌入，不是预留文字）

输出 `<work>/build/说明书自检.json`；有硬性违规时 exit 1，先改再交付。

## 四、截图

必须实拍运行中的界面（`make_screenshots.ps1`），不许用设计稿冒充；出 `截图来源清单.json`（路由/视口/像素/sha256/时间）。
