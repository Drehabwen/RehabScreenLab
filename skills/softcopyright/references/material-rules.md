# 材料规则（鉴别材料页数与行数）

依据《计算机软件著作权登记办法》第十条与常见受理口径。

## 一、页数与选段

| 材料 | 规则 |
| --- | --- |
| 源程序 | 超过 60 页提交**前 30 页 + 后 30 页**；不足 60 页提交全部 |
| 文档（说明书/操作手册） | 同上；本项目控制在 **35–59 页**，可整本提交，避免拆前后 30 |
| 页码 | 提交件内部连续编页（1–60），页眉含软件全称 + 版本号 |

## 二、每页行数（最容易补正的地方）

- 程序：**每页不少于 50 行**；我们固定 **60 行**。
- 文档：**每页不少于 30 行**（封面、末页、纯图页可豁免，但别整页只有一张图）。
- 空行**不算**有效程序行：排版前必须剔除空行，否则会出现"60 个行位里只有 48 行有字"。

## 三、代码材料的表示方式

- 只放代码，不夹大段中文说明；文件之间可用一行注释分隔：`# ===== path =====`（前端用 `//`）。
- 保持原始缩进、换行、大小写；制表符按 4 空格展开。
- 单行超过 118 显示列时**确定性折行**（全角按 2 列），续行缩进 4 空格。
- 末尾不足一页的行裁掉，保证申报版最后一页是满页。
- 代码字体用等宽（Consolas），字号 7.5pt、行距 11.6pt，A4、页边距 15/12mm。

## 四、选材排序（决定"程序开头/结尾"是否成立）

必须**先分组再排序**，否则后端 `features/__init__.py` 这类根文件会掉到前端之后，"程序结尾"就不是结尾：

1. 后端：`main.py` → `core/` → `shared/` → `api/` → `features/<业务模块>/` → `migrations/`
2. 前端：`main.tsx` / `App.tsx` → `shared/`(api→config→i18n→types→components→layout) → `features/`
3. 其它自研源码

排除：`node_modules/ dist/ build/ .venv/ __pycache__/ .git/`、测试文件、生成代码、二进制与资源。
不得为凑页数编造代码；不足 60 页就如实提交全部。

## 五、可追溯

- 选材先落 `code_selection.json`（每文件 `selected / start_line / end_line / reason`），再生成文档。
- 保留 `源程序文件清单.csv`（序号/路径/源码行数/文档行数/选材理由）与 `源程序统计.json`。
